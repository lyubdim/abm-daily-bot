# Демонстрация для руководителя проекта

## Что будет передано

- ссылка на Telegram-бота `@abm_club_daily_bot`;
- персональная одноразовая ссылка подключения к профилю Odoo;
- ссылка на тестовую задачу в портфеле `PORTF-008 Управление клубами`;
- ссылка на GitHub-репозиторий с кодом, CI, журналом разработки и результатами E2E.

Секреты Odoo, Telegram и AI в этот пакет не входят.

## Самостоятельная проверка за 10 минут

1. Открыть персональную Telegram-ссылку и нажать **Start**. Бот подтвердит связь с
   профилем Odoo; повторно применить эту ссылку с другого Telegram-аккаунта нельзя.
2. Выбрать `/daily`. Бот покажет только назначенные проверяющему задачи из портфеля
   `PORTF-008`, проект, дедлайн, текущий этап и кнопку перехода в Odoo.
3. Написать короткий прогресс и выбрать этап кнопкой. Завершить опрос командой `/skip`.
4. Открыть задачу кнопкой **Открыть в Odoo** и проверить новый этап и комментарий
   `[ABM Daily Bot]` в истории общения.
5. Снова открыть незавершённую задачу через `/daily`, выбрать **Есть затруднение**,
   описать проблему и проверить конкретную рекомендацию в Telegram и Odoo.
6. Открыть `/weekly`, выбрать одну или несколько задач недели и подтвердить выбор.
7. Для роли PM проверить `/status`, `/deadlines` и `/digest`.
8. Выполнить `/health`: PostgreSQL и Odoo должны быть отмечены зелёными, очередь не
   должна содержать ошибок; после подключения API ключа AI также отмечается зелёным.

## Как подключаются сотрудники

1. PM отправляет боту `/invite email@company.ru member`. Вместо почты можно указать
   точный Odoo user ID; для руководителей доступны роли `pm` и `tech_lead`.
2. Бот находит активный профиль Odoo и создаёт персональную ссылку на 7 дней.
3. Сотрудник открывает ссылку своим Telegram-аккаунтом. Ссылка закрепляется за первым
   аккаунтом и больше не может быть использована другим человеком.
4. Команда `/whoami` показывает текущую связь. `/daily` запрашивает Odoo только с
   фильтром по идентификатору этого сотрудника, поэтому участники не видят чужие задачи.

Пароли сотрудников не передаются Telegram-боту. Для всех обращений к Odoo используется
отдельная сервисная учётная запись с минимально необходимыми правами.

## Ожидаемый результат

В текущем локальном режиме проверяющему не нужны Docker или командная строка, но
компьютер разработчика с запущенным контейнером должен быть включён во время демонстрации.
Бот читает реальные задачи связанного портфеля, а изменения видны в production Odoo.
Повторный ответ по одной задаче за день обновляет существующую запись, а временная
недоступность Odoo не приводит к потере ответа. После серверного deployment Telegram
будет работать независимо от компьютера разработчика.

## Границы демонстрационных данных

Для проверки используется отдельная задача с префиксом `[BOT TEST]`. Она нужна, чтобы
не менять рабочие задачи команды. После приёмки её можно архивировать по согласованию.
