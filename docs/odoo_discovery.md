# Odoo API Discovery

Документ фиксирует воспроизводимую проверку интеграции без сохранения секретов.

## Что уже установлено

- Test stand отвечает как Odoo `18.0-20260119`, база называется `odoo`.
- Production отвечает как Odoo Enterprise `18.0+e-20250218`.
- На обоих стендах доступен XML-RPC endpoint.
- Публичный список баз production закрыт с `403`, что нормально для production.
- Веб-вход в test stand подтверждён через email-код; учётная запись видит модуль
  Project.
- Создан отдельный временный API key для test stand; XML-RPC вернул `uid=94`.
- Подтверждены технические поля задач и CRUD-права на проекты, задачи и стадии.
- Созданы изолированные тестовые записи и успешно проверены `search_read`,
  `write` для `stage_id`/`state` и `message_post` с URL.
- Production не изменялся.

## Безопасная повторная проверка

После заполнения локального `.env` выполнить:

```bash
abm-odoo-discover
```

Команда выполняет только чтение:

1. получает версию Odoo;
2. проверяет аутентификацию;
3. читает метаданные значимых полей `project.task`;
4. получает стадии `project.task.type`;
5. выводит до пяти задач текущего пользователя.

Пароль и API key в вывод не попадают. Результат можно сохранить как приложение к
отчёту по практике после удаления названий реальных задач, если они являются
конфиденциальными.

## Критерий готовности интеграции

Discovery считается пройденным, если получены `authenticated_user_id`, список
стадий и хотя бы метаданные модели `project.task`. На test stand этот критерий
выполнен, а `write` и `message_post` дополнительно проверены на задаче `id=4`.

Запись на production до согласования интеграционного пользователя не выполняется.
