## Defects found during acceptance

1. Empty optional `PUBLIC_BASE_URL` stopped application startup. Fixed in `6c66f1d`.
2. An existing Odoo user mapping caused a uniqueness failure on a new Telegram binding.
   Fixed in `24f18fc` with a regression test.
3. Windows startup diagnostics reported a false stop while polling was active.
   Fixed in `18c56b0`.
4. Telegram-based outbox keys created a duplicate after an account rebind. The key now
   uses the stable Odoo user ID and adopts the latest legacy row.
5. Task links opened the customer portal preview instead of the internal task card.
   Links now target `/odoo/project.task/{id}` for daily and assignment notifications.
6. Initial `message_post` escaped formatting in the internal chatter. New daily and
   blocker messages now explicitly pass `body_is_html=True`.
7. The first UI used five technical Odoo states, while the test project workflow has
   three stages: `К выполнению`, `В работе`, `Готово`. Buttons now load project stages
   dynamically and persist both `stage_id` and the compatible technical state.
8. The first dynamic query mixed global personal stages with project stages. Project
   stages are now selected first; global stages are only a fallback for projects with
   no dedicated workflow.
9. Result and blocker-resolution fields accepted malformed URLs. Both handlers now
   require a complete HTTP(S) URL without whitespace and retain the input state on error.
10. The first production preview showed a large login-page preview and duplicate daily
    output. Assignment links now use an inline button, and Windows launch scripts stop
    previous Compose instances before starting exactly one bot.
11. Production `message_post` rejected the daily comment because the API user has no
    configured sender email. Bot-authored task history now uses direct internal
    `mail.message` records, which do not depend on outbound mail configuration.
12. The production stage is named `OING` in Odoo. Telegram now presents localized
    labels (`В очереди`, `Планирование`, `Срочно`, `В работе`, `Тестирование`, `Готово`)
    while callbacks continue to write the real Odoo stage IDs.
