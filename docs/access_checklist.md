# Access Checklist

Лучше не передавать личные пароли. Безопаснее создать отдельные временные ключи и тестовые аккаунты с минимальными правами.

## Odoo

Нужно:

- URL Odoo: test `http://204.12.253.210:8070`, prod `https://abmapex.ru`.
- Версия Odoo: test `18.0-20260119`, prod `18.0+e-20250218`.
- Название базы: test `odoo`, prod нужно узнать после входа.
- Интеграционный пользователь Odoo.
- API key или логин/пароль для XML-RPC.
- Права на чтение задач `project.task`.
- Права на запись статуса задачи.
- Права на запись комментариев в chatter.
- Права на просмотр пользователей/исполнителей.
- Права на настройку automated actions/webhook, если хотим US6 без polling.

Что нужно выяснить:

- технические названия статусов;
- какие статусы показывать кнопками;
- есть ли кастомные поля для результата/затруднений;
- как определить PM и техлида проекта;
- можно ли создать тестовую задачу для безопасных экспериментов.

Для test stand переданная пара не проходит аутентификацию. Нужны подтверждение
активации пользователя и новый временный пароль/API key от администратора.

Для production лучше запросить отдельного integration user или API key. Выданные регистрационные данные администратора не стоит использовать как постоянный секрет бота.

## Telegram

Нужно:

- токен бота от BotFather;
- username бота;
- список Telegram username участников;
- список Telegram username PM/техлидов;
- решение: webhook на сервере или polling для локальной разработки.

## AI provider

Нужно:

- API key;
- выбранная модель;
- лимиты/бюджет;
- правило: не отправлять в AI больше контекста, чем нужно для конкретной задачи.

## GitHub

Нужно:

- название репозитория;
- публичный или приватный репозиторий;
- GitHub username владельца;
- решение, кто будет иметь доступ;
- Personal Access Token или создание репозитория вручную пользователем.

Важно: токен GitHub не должен попадать в `.env.example`, README, issues или историю commit'ов.

## Deploy

Варианты:

- локально для демонстрации через polling;
- VPS с HTTPS для Telegram webhook;
- Docker Compose на сервере;
- Render/Fly.io/Railway, если разрешены внешние сервисы.

Нужно:

- домен или публичный HTTPS URL;
- доступ к серверу;
- способ хранить секреты;
- резервное копирование PostgreSQL.
